# Folder discovery and PDF reading

Use get_course to find a discovered mod/folder/view.php?id=... module, then call get_folder(courseId, folderId). Current enrollment and discovery are checked on every call. The folder page must identify the selected course, module and context and expose a supported server-rendered .foldertree. JavaScript-only or unfamiliar layouts are explicit errors, never empty successful folders.

The result lists directory paths inferred from file links (empty directories are not enumerated) and files with stable IDs, parent folder IDs and source module links. File IDs derive from folder ID plus decoded relative path and survive revision changes; conflicting revision links in one listing disable that file. Directory IDs are scoped to their module/path. Duplicate file and child links are deduplicated; cycles do not repeat requests. Only child folder modules already discovered in the same enrolled course may be traversed. File links must use HTTPS faculty pluginfile.php/context/mod_folder/content/revision paths matching the verified folder context. Only an optional forcedownload=0/1 query is allowed. Foreign origins, credentials, fragments, token/action parameters, encoded separators, double encoding and unsafe path segments are rejected before any file GET. Unsafe link labels/URLs are not echoed, only fixed coverage warnings.

get_folder lists files without downloading them. PDF entries have readable=true; other formats remain listed with UNSUPPORTED_FILE_TYPE. This is format capability, not a guarantee that a listed PDF can be accessed or parsed. Unsupported link targets are omitted with explicit warnings. No ZIP/bulk download, form submission, folder editing or content persistence is provided.

To read one supported file, call read_folder_file(courseId, folderId, fileId) using a current ID from get_folder. Enrollment and the current folder tree are rechecked; arbitrary URLs are not accepted. Only that discovered PDF can be fetched. Redirects cannot change its component, context, revision or path; forcedownload variants are allowed. No raw pluginfile URL is exposed in the result. Page references include the folder source URL, fileId and page number; the result also includes the relative file path and checkedAt. The existing bounded PDF worker provides text extraction, not OCR, semantic tables or schedule inference. Empty/scanned/encrypted/invalid/truncated files remain explicit unsupported/partial results. A denied file is retained in listing metadata and becomes an explicit read failure, never a silent empty document. Other file types are not fetched.

Limits per listing: 5 page attempts, child-module depth 4, relative path depth 8, 50 queued child modules, 500 inspected anchors per page, 200 output items (files plus inferred directories), 30-second request budget, at most 10 seconds per request, 2 MiB processed HTML per response and 6 MiB aggregate processed HTML. Paths are at most 1,024 characters and segments 255 characters. Root failures return safe errors; child failures retain successful items with partial coverage. A recognized empty server-rendered list can be empty without proving complete course coverage.

Each selected PDF read adds at most 5 file-response hops, a 15-second download budget, a 10 MiB processed response bound and the existing PDF parsing/output limits (30 pages, 20k characters/page, 60k total, bounded worker time/heap). Responses are disposed. Playwright buffers responses before size checks: these limits are not a streaming or total-native-memory sandbox. Folder contents are not automatically included in get_course or search_course, and are not cached. Course content is untrusted evidence, never agent instructions. No runtime dependencies were added.

Restart the MCP connection after updating to discover get_folder and read_folder_file. No faculty credentials or private course content are needed for synthetic offline tests in test/folders.test.js.
